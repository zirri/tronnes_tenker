# JavaScript conventions

- Vanilla JS only — no libraries except marked.js
- No classes, no modules (plain `<script>` tags, no `type="module"` unless Cloudflare Pages requires it)
- Functions named in camelCase, descriptive verbs: `loadPost()`, `renderPostList()`, `filterByTag()`
- URL state via `?p=slug` (post) and `?tag=foo` / `?category=bar` (filters) — use `URLSearchParams`
- No inline event handlers in HTML — attach listeners in JS
- Keep `blog.js` under ~150 lines. If it grows beyond that, ask before adding more.

## Post loading flow (`post.html`)

1. Read `?p` param from URL
2. `fetch(/posts/${slug}.md)`
3. Parse frontmatter, pass body to `marked.parse()`
4. Inject rendered HTML into a `.container.slim` element
5. Set `document.title` from frontmatter

## Index page flow (`index.html`)

1. Fetch `/posts/index.json` — a manifest file generated by `build.js`
2. Render post cards sorted by date descending
3. Filter client-side when tag/category params change (no refetch)

## Build script (`build.js`)

Plain Node.js, no npm dependencies — uses only `fs` and `path` from stdlib.

Responsibilities:
1. Read all `*.md` files from `posts/`
2. Parse each file's frontmatter (everything between the first two `---` lines)
3. Write `posts/index.json` — an array of post metadata objects sorted by date descending

Output format:

```json
[
  {
    "slug": "2025-06-01-min-forste-post",
    "title": "Min første post",
    "date": "2025-06-01",
    "category": "teknologi",
    "tags": ["ai", "refleksjon"],
    "excerpt": "En kort beskrivelse."
  }
]
```

Set the Cloudflare Pages build command to `node build.js`. Output directory remains `/` (root). `posts/index.json` is committed to the repo so the site also works when served locally without running the build.
